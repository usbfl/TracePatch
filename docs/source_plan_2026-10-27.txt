TracePatch 项目思路整理
一 概览流程
研究一条信息被纠正后，Agent 如何同步修正相关记忆、当前结论和后续计划，并避免旧错误再次被
写回。定位为 Harness 的验证与纠正机制，连接跨任务外部产物更新和任务内上下文适应。[1]

研究对象
长期记忆：跨会话保存的用户事实、偏好、事件经历、摘要和派生结论；对应文章中的语义记忆与情
景记忆，可复用流程属于程序记忆，后续按需扩展。
短期工作记忆：当前有效的消息与工具观察、已加载的长期记忆、会话摘要，以及状态栏中的 TODO、
当前结论、完成进度与剩余预算；本次计划属于工作状态。[1]
共同约束：“根据当前用途安排修复”贯穿两方向，比较修复质量、有效工作保留与新增成本；证据
不足只按待核验规则处理，不单列研究方向。

项目概况
背景：信息更正后，相关记忆、结论和计划可能未同步更新，旧错误还可能经摘要与记忆写入再次被
采用。
现状：v0.1 已完成离线结构化原型，支持依赖补查、预算核验、规则重算与版本记录；真实 Agent 续
做与后续写回尚未验证。[2]
困难：依赖漏记使影响范围不完整；扩大检查又增加成本，需要兼顾漏修、误修和有效内容保留。
改进：沿长期知识更新与短期任务接续两线推进，完善用途调度、状态与计划更新，再用持续写回实
验检验修复效果。

二 具体技术设计
1 知识表示与更新边界
让重要结论带上简短的依据记录：借鉴带来源与情境的 JSON Cards，为每条知识保存“实体、断言、
作用域、有效时间、版本、来源、依赖”，并绑定结论采用过的依据版本。[1]

新信息的含义        记录与推论如何更新

过去记错了         更正同一对象与范围的旧断言，旧版本标记失效，重新核验相关推论。

现实发生变化        保存分段有效的时间版本，按任务时间选择事实及相应结论。

条件或范围不同       按主体或作用域并存，检索与执行时过滤适用对象。

分开保存历史记录和当前有效上下文：原始轨迹与证据保留供回查；知识层保存可修订版本；服务层
从有效版本生成摘要、分块与检索索引。变更先提出局部修改、核对原证据，再发布有效版本并更新
派生物。[1]

2 依赖补查与用途调度
先查已记录的依赖，再用文本与实体检索补充候选；将记忆检索、原文读取做成工具，可比较 Agentic
RAG 的多轮补查。相关性只决定查谁，修改结论仍需核对证据。
长期侧比较历史频率、最近使用与核验成本；短期侧优先检查下一步动作、当前约束及“已完成”判
断。核验后分别更新错误结论、保留仍成立内容，或标记待核验。

3 在 ReAct 循环中修复当前状态与计划
用户更正或工具新观察进入后、下一轮模型调用前，检查相关结论与 TODO；失效的完成判断重新核
验，仍有效的资料和步骤保留，再选择局部重算或重新规划。
由代码维护 Agent 状态栏，汇总“当前有效事实、本次修改、有效结论、TODO 与进度、剩余预算”，
放入上下文末尾；状态栏自身也纳入更新检查。[1]

4 上下文更新、压缩与写回
保持系统提示词与工具定义稳定，比较“每轮替换末尾状态”和“持久追加最新状态”：前者减少陈
旧状态，后者有利于前缀缓存复用；同时记录旧错复用与缓存成本。[1]
采用带来源的上下文感知压缩，保留当前任务需要的结论、时间、范围与依据；“检查新摘要和记忆
写入”时核对有效版本，防止旧错误重新进入知识层与下一轮上下文。
可选扩展：文章提到的 KV Cache 局部编辑可作为后续探索，首轮先在消息、状态栏和计划层验证；定
期全量整理仅作为可选对照。[1]

评价重点
质量与成本：新信息采用率、受影响结论修复率、正确内容与有效工作保留率、任务接续成功率、旧
错误复用或重新写回率，以及新增核验与运行成本。
允许按时间和范围保留历史版本；重点检查旧错误是否被当作当前依据，并同时看可回答比例，避免
把过度隔离当作修复成功。
