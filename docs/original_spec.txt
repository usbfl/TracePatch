==================================================
1. 项目目标与研究边界
==================================================

核心问题：
当一条长期记忆被明确纠正时，依赖它产生的推断、摘要或缓存可能仍是错的。显式依赖记录又可能缺失。在有限核验预算内，能否优先找出并修复最可能影响后续回答的记忆，同时保留仍然正确的信息？

主假设：
在相同核验器、证据、数据快照与预算上限下，结合可见依赖、文本/实体线索、历史使用和可观察成本的核验调度，可能优于只修根、只追踪可见图和简单全量扫描。
这是待检验假设，不要求 TracePatch 胜出。

v0.1 的明确范围：
- 结构化 Agent 记忆修复实验台，带自然语言展示文本。
- 每个主实验场景只有一次可信、已诊断、已定位到根记忆的“旧断言本来就是错的”更正。
- 显式依赖索引不完整；一部分原始执行记录仍可通过预算化读取恢复。
- 原始记录真正丢失时允许 UNKNOWN；不承诺恢复无法取得的证据。
- 研究调度与修复机制，不训练基础模型，不做模型权重编辑。
- 离线实验可以验证受控环境中的机制；不能直接宣称证明真实自然语言 Agent 的纠错能力。
- v0.1 评价修复完成后对持久记忆的只读复用，不模拟修好后又发生新的写入污染。

不纳入首版主实验：
任意错误的自动诊断、错误纠正指令的真实性判断、开放域知识冲突解决、多人权限治理、完整工具 Agent、真实网页操作、多轮新错误注入、GPU 训练。

“过去就记错了”“现在状态变了”“不同条件下偏好不同”必须区分。后两类作为边界语义测试，不混进主实验宣称通用时态推理能力。

3. 数据模型：版本化，不硬删除
==================================================

每条记忆是一个单一的结构化声明。展示文本可以像一句摘要，但不能一条记录包含多个无法单独评分的主张。

MemoryRecord 至少包含：
logical_id、version_id、kind、owner_id、scope_id、claim_key、
value（有类型的 int/bool/string，不能把 bool 当 int）、
text、entities、created_step、valid_from、valid_to、
status、capsule_id、capsule_size_hint、last_used_step、use_count。

kind 至少支持：
- fact：直接事实；
- derived：规则推断；
- cache：持久化的派生结果，使用同一记忆机制，不另建复杂缓存系统。

状态：
- ACTIVE：可用于正常当前查询；
- QUARANTINED：不可用于正常查询，等待或未完成核验；
- SUPERSEDED：已有后继版本，保留审计历史。

UNKNOWN 是核验结果，不是“事实值为假”。
QUARANTINED 必须带 reason，如 missing_capsule、missing_evidence、budget_exhausted、conflicting_evidence、invalid_model_output。
可增设不可核验状态，但它在查询与统计上必须等同不可用，不能隐藏误伤。

每次修复用事务创建后继版本，旧版本标记 SUPERSEDED。
同一 logical_id 在一个有效时间/作用域内最多有一个 ACTIVE 当前版本。
仍然正确的声明可创建同值新版本以绑定新支持证书。
保留原始文本、旧版本、操作原因、证据和预算账本，不做物理删除。

CorrectionEvent：
event_id、target_logical_id、target_version_id、owner_id、scope_id、
kind、new_value、effective_from、effective_to、issued_step、trusted_source_ref。

主实验 kind=CORRECTION：修正指定作用域/有效区间内本来错误的断言。
UPDATE：旧值此前有效，新值从指定时间生效，不能抹去此前历史。
CONTEXTUAL_ASSERTION：不同 scope 的偏好可以并存，不能自动覆盖。
v0.1 对上述边界类型实现明确的记录/查询测试；主修复实验只运行 CORRECTION。

==================================================
4. 三层信息隔离
==================================================

数据必须分为三层，不能把完整 Episode 对象交给修复器：

A. public/
- 初始记忆记录和可见依赖边 G_obs。
- 已知根更正事件。
- 更正前的访问历史。
- 不透明 capsule_id 与公开粗略大小提示。
- 可以供候选排序使用的正常元数据。

B. environment/
- 原始执行记录 capsule。
- 原始证据文档及版本。
- 当前更正覆盖关系。
这是能够通过计费网关查询的环境资料，不是评价 gold。

C. evaluation/
- 完整生成依赖图 G_true。
- 更正后的精确值、原先错误集、仍正确集。
- 未来问题、答案、分层标签。
- 注入类型、隐藏生成参数、缺边真值。

修复策略和核验器都不能读取 C。
选择器不能直接打开 B，只有 EvidenceGateway 可读。
RepairContext 只给：
MemoryView、ObservedGraph、EvidenceGateway、BudgetLedger、PreCorrectionUsage。

run 在 evaluation/ 完全不存在时也必须能够完成修复与状态冻结。
evaluate 才能读取 evaluation/。
不要让 repair/ import evaluation/。
这属于接口与测试层面的实验隔离，不宣称同进程 Python 能抵御恶意代码的文件系统访问。

公开记忆禁止包含：
完整 recipe、真实父节点全集、隐藏证据绑定、is_corrupted、
true_value、gold_affected、未来问题 ID/频率、完整真实子树成本。

ID 使用不透明稳定标识，不编码“错误/正确”“根/后代”等真值。
不要依赖 Python 进程随机 hash；使用规范序列化与 SHA-256。
内部生成种子和缺失掩码不提供给调度器以重建隐藏数据。

==================================================
5. 可预算化恢复的原始执行记录
==================================================

每条非更正根记忆有一个不透明 capsule_id。
只有支付读取成本后，READ_CAPSULE 才返回：
- 该记录原始生成规则；
- 操作数的 logical_id 与当时版本绑定；
- 直接事实的 source_id、source_version、field_key；
- 当时的输入/执行轨迹；
- 可重放所需的信息。

capsule 是实际原始记录，不是“这条记忆是否正确”的标签。
生成器创建后不得由评估器偷偷补写答案。
capsule 丢失必须返回 NOT_FOUND，不能从 G_true 重建。

读取后恢复的依赖可以写入可见图；应记录其来自哪次付费读取。
区分：
- observed/influence edge：记录计算曾读取或可能使用哪个输入；
- verified support：本次得到某个值实际需要的证据集合。
一个可见影响边不是结论错误的证明。

EvidenceGateway 至少提供：
read_capsule(capsule_id, budget)
read_source(source_id, source_version, field_key, snapshot_id, budget)

v0.1 不需要开放式全文检索证据；capsule 提供可重读绑定即可。
若实现搜索，包含事实值的摘要/预览也必须计入读取成本，不能免费泄漏证据。

对旧 capsule 中的绑定，要经当前更正映射解析：
已撤回的旧根版本不能因重放原始日志而重新成为有效值。
所有核验在固定 evidence_snapshot_id 上进行。
读取历史有效记录时必须尊重 scope 与有效期。

==================================================
6. 有限规则与严格核验语义
==================================================

为了可实现，使用有限、类型化运算：
COPY、EQ、GE、LE、AND、OR、NOT；常量为有限 int/bool/string。
可增加简单 MIN/MAX，但非必要。
每个节点操作数不超过 4，主实验 DAG 深度不超过 4。
禁止执行任意生成代码、eval/exec、动态 import。
拒绝未知运算、错误类型、循环、超长记录和超界深度。

核验接口：
verify_and_rebuild(logical_id, snapshot_id, context) -> VerificationResult

结果至少包括：
outcome（SUPPORTED_SAME / REPLACED / UNKNOWN）、
old_value、new_value（若已知）、
实际读取的证据版本、恢复的边、支持证书、
消耗的工作单位、读取/执行事件、失败原因。

执行规则：
1. 如果当前根有可信更正证书，使用已提供的新值。
2. 否则先经网关付费读 capsule。
3. 直接事实：按绑定付费读原文，再提取其字段。
4. 派生记忆：递归核验必要子输入；不能因为子记忆 ACTIVE 就信任旧值。
5. 使用实际已取得的输入执行有限规则。
6. 得到确定结果时创建/恢复有支持的新版本；不确定时隔离当前目标。

UNKNOWN 传播：
- AND：任一确定 FALSE 即 FALSE；全部 TRUE 才 TRUE；否则 UNKNOWN。
- OR：任一确定 TRUE 即 TRUE；全部 FALSE 才 FALSE；否则 UNKNOWN。
- NOT(UNKNOWN)=UNKNOWN。
- 比较/COPY 需要对应输入已知，否则 UNKNOWN。
- 确定的 FALSE 可以是合法、正确、可用的新记忆。

独立支持必须覆盖一个完整分支。
例如 (A AND B) OR (C AND D)，A 失效时，C 与 D 都成立才足以支持 TRUE；
只知道 C 成立不够。
依赖更正根的结论也可能保持正确，例如 16 改为 8，判断“>=6”仍为真。

按 capsule 中预先固定的操作数顺序执行，所有方法相同。
允许按上述三值语义短路；支持证书应只包含足以支持该结果的完整证据。
确定性离线解释器是共享核验器，不为 TracePatch 提供专属能力。

证书与缓存：
- 绑定 evidence_snapshot_id、纠正事件、所用叶证据版本、规则版本、核验模式。
- 缓存键必须包含这些语义版本。
- 同一运行内可以复用已核验子树与已读原文。
- 跨方法/预算运行的逻辑缓存独立，不能免费继承其他方法已经花钱获得的证据。
- 记录影响边不自动授予支持证书。
- 不完整审计不能提交“已核验”标记；已完成子树可以原子提交并用于后续核验。

==================================================
7. TracePatch 候选与调度：确定规则
==================================================

对 root_only 之外的方法：
- 应用已知根更正；
- 用 G_obs 找到同 owner/scope、有效区间相容的可见后继 D_obs；
- 将这些后继加入队列并暂时隔离，等待核验。
- 跨用户或不相容作用域不能传播。
图可能含伪边；误隔离要在指标中体现。

TracePatch 的候选：
C = D_obs ∪ TopK_semantic
TopK_semantic 只从合法 owner/scope/time 的记录选，默认 K=16。
在修复开始时，用初始公开文本固定拟合一次 TF-IDF，固定选取一次 TopK；
从语义补充池排除初始 D_obs、更正根与已有当前快照有效证书的节点。
不得每处理一个节点就补足 K，避免语义扩展悄悄变成全量扫描。
后续只通过付费恢复的图边扩展候选；s(m) 保持初始值，g(m) 和 c_hat(m)
可根据已合法获得的边与证书重新计算。队列排除已完成的当前版本。
语义相似只用于提出候选，不能直接生成因果边、判错或硬删除。

推荐完全离线的相似度：
- entity_overlap：实体集合 Jaccard，空集合分母时为 0；
- text_similarity：字符 3-gram TF-IDF cosine；
  TF-IDF 只在本场景公开记忆文本与纠正文本上拟合，Unicode NFKC+casefold；
- s(m)=0.4*entity_overlap+0.6*text_similarity。
- 纠正查询文本由根旧文本与更正说明组成。
实现空文本、全零向量、并列排序，不能要求联网 embedding。

风险启发式：
g(m)=0.8^(d-1)，若存在长度为 d 的可见根到 m 路径；否则为 0。
r(m)=max(g(m), 0.7*s(m))。
这不是校准概率，不要在 UI 或论文里称为真实错误概率。

历史使用：
u(m)=log(1+use_count(m))/log(1+max_count)，max_count>0 时；
若整个场景没有历史访问，所有 u(m)=1。
只能用纠正前历史，不能使用测试查询或实际未来频率。

可观察成本估计：
c_hat(m)=max(1,ceil(capsule_size_hint/2048))
         + 1
         + count(当前 G_obs 中尚无有效证书的直接前驱)。
缺少大小提示时首项取 1。
c_hat 只是排序用估计，真实收费以账本为准。
不能用 G_true 中的子树大小或即将读取的隐藏配方估计成本。

优先级：
P(m)=r(m)*(0.25+0.75*u(m))/max(1,c_hat(m))。

并列按 created_step，再按 logical_id。
系数、K、特征和规则必须写进配置并在测试前冻结。
不要在测试结果上自动调整权重。

调度：
- 每次挑选最高优先级未完成候选，调用共享核验器。
- 语义补充候选在被实际选中审计前保持原有状态。
- 被选中的目标在审计期间隔离；UNKNOWN 保持隔离。
- 完成核验恢复/替换，所有修改写日志。
- 付费读取恢复的边合入 G_obs。
- 如果新发现的影响关系扩大根的可见后继，使用同一规则扩展队列/隔离；
  对已有当前快照有效证书的节点，不重复撤回。
- 递归核验的前驱也要计费、记录；它们不需要先在顶层候选池内。
- 当剩余预算不足下一原子操作时，统一结束本次修复运行的全部核验，
  不继续挑选其他目标，不反复重选当前目标；允许账本有未花完的预算。
  该目标返回 UNKNOWN/budget_exhausted，已完成子树可保留，未完成工作不提交。
  五种方法使用同一停止协议；预算用尽正常结束，不记作程序失败。
- 对确定不可恢复的目标，每个快照最多尝试一次；不能无限重复读取。
- 没有候选或预算耗尽即可结束，不要求花完预算。

首版采用“优先复用有效证书，否则付费重读与重算”的统一执行器。
不要额外引入一个未定义的 LLM 去选择修复动作。

==================================================
8. 基线与消融
==================================================

所有预算内方法使用相同数据快照、证据、规则、版本语义、核验器与预算上限。

必须实现五个主方法：

1. root_only
只把已知错误根替换为正确根，不修复下游。
在本结构化设置中，“删错根再写新值”和“根字段最新覆盖”可能等价，
因此合并，不伪装成两个不同基线。

2. graph_only
候选仅为当前可见图后继；隔离后按最短可见距离、created_step、ID 审计。
恢复出的边使用与其他方法相同的更新规则。

3. expanded_fifo
与 TracePatch 使用相同语义补充候选、状态规则与动态候选扩展；
按 created_step、ID 调度。
这是检验排序贡献的直接对照。

4. tracepatch
使用第 7 节的风险×历史使用/可观察成本排序。

5. full_scan
同样先隔离可见后继，但将全部同作用域有效记忆加入审计队列，
按 created_step、ID 扫描，仍受相同预算限制。
不要故意先隔离所有无关记录来削弱此基线。

诊断参考：
- full_audit：共享核验器扫描全部记忆，核验预算不限制；
  仍不能读取 gold，也不能恢复真正丢失的原文。
  单列实际成本，不混入同预算排行榜。
- all_quarantine：仅用于指标单测/少量诊断，验证“全部隔离”会损失覆盖率。
- 允许给一个 no_repair 展示快照，但它不是主要同预算对照。

消融配置必须能够运行，但不默认跑满：
- no_semantic：不扩展语义候选，其他调度规则保持；
- no_usage：令 u=1；
- no_cost：令 c_hat=1。
消融继承相同实际收费，不能因为去掉成本特征而不记成本。

不要把 graph_only 叫作 memory-rollback 官方复现；
不要把 full_scan 或 tracepatch 叫作 MemoRepair 复现。

==================================================
9. 数据生成：可控、非平凡、没有真值捷径
==================================================

主领域为虚构的设备、游戏/软件需求、用户条件和推荐资格。
使用虚构产品名，不把合成规格写成真实游戏配置。
主张值采用 bool/int/string，查询可精确评分。

生成流程：
1. 生成事实原文、有限计算 DAG 和正确结果。
2. 选一个根事实，将其初始记忆值替换为错误值。
3. 用错误记忆值计算下游初始派生记录和缓存，真实记录生成过程。
4. 原始证据仍保留；capsule 记录当时的绑定和生成规则。
5. 从影响边中遮蔽一部分，形成 G_obs。
6. 独立决定哪些 capsule 无法再读取。
7. 生成纠正前访问日志；在修复入口提供可信根更正。
8. 保存隐藏真值、未来查询和评分材料；不得发给修复器。

不能只选择“改根值一定导致所有后代变错”的简单图。
每个主场景至少包含：
- 一个深度至少 2 的错误传播链；
- 至少 3 个纠正后值需要变化的非根记录；
- 至少 3 个虽然受根影响但值仍正确的记录；
- 至少 3 个无关正确记录；
- 一个具有独立完整支持分支的 OR 情形；
- 同主题但不受影响的干扰记录。
生成条件不满足时确定性重采样，记录生成尝试次数。

主条件：
- 缺边率 delta ∈ {0, 0.25, 0.5, 0.75}；
- 默认 capsule 丢失率 rho=0；
- 各方法共享相同遮蔽结果；
- 用每条边固定随机数实现嵌套遮蔽，较高缺边率不能恢复较低缺边率删掉的边。

压力条件作为独立配置，不默认做笛卡尔积：
- capsule 丢失率 0.1、0.3，与是否错误及缺边掩码独立；
- 优先遮蔽靠近根的边；
- 加入少量保持无环的伪边；
- 历史使用与未来使用发生分布变化；
- 更多节点或更深传播链。
压力配置可以分阶段实现，但必须明确哪些实际运行、哪些只提供配置。

访问与未来查询：
- 先生成独立于注入故障位置的潜在使用权重。
- 纠正前访问日志和未来查询，分别从该权重独立抽样。
- 修复器只能见前者。
- 主要查询集采用未来使用分布，另提供均匀覆盖各记忆目标的评价集。
- 历史使用分布偏移压力测试单列，避免假设历史永远预测未来。
- 查询、隐藏权重、未来答案均在 evaluation/。
- 不因为某个方法表现不好而重生成测试场景。

拆分：
- dev/test 按完整基础场景与实体集合拆分，不能把同一图的删边副本分到两边。
- 缺边率、预算、方法等是同一基础场景上的配对变体。
- 至少包含内容哈希、生成器版本、参数、独立随机流版本。
- 根选择、图生成、遮蔽、capsule 丢失、访问历史、未来问题使用独立随机流。

10. 固定演示：展示错误传播与正确记忆保留
==================================================

提供一个不依赖 API 的固定案例：
- 保存的设备内存误记为 16 GB，可信更正说明实际一直是 8 GB。
- 虚构游戏 A 需要 12 GB：旧“可以运行 A”为 TRUE，应变为 FALSE。
- “推荐 A”依赖该兼容性结论，构成第二跳错误。
- 虚构游戏 B 只需 6 GB：旧“可以运行 B”依然为 TRUE。
- “用户喜欢回合制策略”来自独立证据，应保留。
- 至少一个结论有另一条完整独立支持路径。
- 遮蔽兼容性 A 到推荐 A 的一条索引边。
- 提供低预算与充足预算的结果。

展示：
纠正前后表格、可见依赖图、每次读取和核验的证据与成本、
被替换/恢复/隔离的记录、未处理的残留错误、最终只读查询。
隐藏真图只能在修复冻结后的“评价诊断”视图展示。
不得把隐藏边提前传回算法，也不能硬编码 TracePatch 必须获胜。

演示结果必须由真实代码执行产生。
这些手工案例用于解释和单测，不混入正式平均性能。

==================================================
11. 预算定义与完整账本
==================================================

主预算使用明确的“核验工作单位”，不是声称统一换算为实际金额：

- 首次读取一个 capsule：max(1,ceil(实际 UTF-8 字节数/2048)) 单位。
- 首次读取一个原文块：同样按字节数计单位。
- 失败/不存在的读取：1 单位。
- 一次新的叶字段提取或有限规则执行：1 单位。
- 同一运行内合法缓存命中：新增工作单位 0，但记录逻辑请求和缓存命中。
- 根更正输入的应用：共同设置步骤，不占核验单位，单列操作计数与时间。
- 候选文本检索、图遍历与打分：不占“核验单位”，必须单独记录次数、
  处理记录数、实际时间；因此不能宣称核验单位代表系统全部成本。

原子操作必须先检查/预留所需单位，再读取或执行。
超过剩余预算就拒绝执行，不可先获取信息再宣布没预算。
EvidenceGateway 用环境层保存并校验的字节长度元数据或文件大小，在不向
调用方暴露正文的情况下计算准确读取成本；预留成功后才返回内容。
正文长度与元数据不符时明确失败，不能先交付正文再补收费。
公开 capsule_size_hint 仅用于排序，不作为实际收费依据。
缓存不能跨方法或不同预算运行获得免费信息。
如为节约物理运行复用已下载字节，逻辑授权、单位和可见信息仍独立计费。

账本至少记录：
planned_budget、spent_units、reserved_units、
capsule_requests/reads、source_requests/reads、
bytes_read、rule_evaluations、leaf_extractions、cache_hits、
candidate_records_scored、graph_visits、
audit_started/completed/unknown、
model_requests、retry_requests、input/output_tokens、
时间、节点状态变化、失败原因。

真实 token 未返回时标记 estimated 或 unknown，不能写成 0。
离线确实没有模型请求时可明确记录 0 次调用。
不配置价格时不输出虚构费用；核验单位不是人民币或美元。
各方法预算上限相同不保证实际时间/token 一样，报告实际消耗。

==================================================
12. offline / live / replay
==================================================

offline：
- capsule 与规则读取完全确定性。
- 原文使用受控模板和明确字段语义，解析器从实际读到的文本得到字段。
- 解析器不得从字段 ID、memory ID 或 gold 反查真值。
- 模板表达能力有限，报告必须说明。
- 可以得到真实的结构化机制实验结果，但不冒充自然语言端到端效果。

live：
- 只替换叶证据字段提取器；图、候选调度、规则执行、数据和查询器不变。
- 模型收到已付费读取的原文、目标字段、类型和作用域，输出 JSON：
  outcome、value、source_id、source_version、quote、reason。
- quote 必须能在已读原文中精确定位，source_id/version 只能来自给定证据。
- 引文存在只证明来源可追溯，不保证模型提取语义正确。
- 无法确定则 UNKNOWN；不允许从常识补值。
- 模型输入不含 gold、未来答案、隐藏依赖或“你应该输出什么”的标签。
- JSON/schema/引用不合法就 UNKNOWN，不做无限格式修复。
- 使用可配置的 OpenAI-compatible 接口，例如通过 httpx；
  base_url、model、API key 环境变量、请求参数都可配置。
- 不硬编码某个真实模型名称、价格或供应商能力。
- TRACEPATCH_API_KEY / TRACEPATCH_BASE_URL / TRACEPATCH_MODEL；
  不把密钥写入日志、报告、源码、压缩包。
- 即使检测到环境中有 key，默认也不能发请求。
- 必须 provider=live 且用户明确传入允许网络的配置/CLI 开关。
- 每次提取最多 2 次网络尝试：初始 + 1 次；
  仅对超时、429、5xx 可重试，其余 4xx 不重试。
- API 尝试和重试另有全局硬上限，预留后才发送。
- 同时设置输入/输出长度、请求超时和上下文预算。
- 数据中的文本是证据，不能当成工具指令或系统提示。

replay：
- 只重放已经记录的实际模型响应，不生成虚构记录。
- 验证源运行、模型参数、请求哈希、提示词版本、证据与规则版本。
- semantic_config_hash 与 runtime/transport 配置分离；
  provider 从 live 改为 replay 或输出目录变化，不应错误地使语义哈希失配。
- 原始 live 模型信息必须保留，不能让不同配置悄悄命中记录。

live_smoke 是接口检查：
2 个场景、1 个缺边条件、1 个预算，先运行 graph_only 与 tracepatch，
全局最多 32 次 API 尝试。它不构成正式五方法比较。
不要在构建阶段自动运行任何真实调用。

==================================================
13. 事务与断点恢复
==================================================

SQLite 保存：
运行/协议、节点版本、边、证据访问、证书、审计动作、预算与模型请求。
确定性的 event_id 防止重复提交。

每个原子动作：
1. 事务中保存 pending 与预算预留；
2. 执行读取/计算/网络请求；
3. 事务中提交结果、收费、状态更新。

离线恢复必须与不中断运行得到相同最终状态、动作顺序与预算；
比较时排除真实墙钟时间。
持久化初始候选/文本快照、当前审计目标、递归核验进度、已授权读取和证书缓存，
或用确定性事件日志完整重建。恢复从首个未提交原子动作继续，沿用原 action_id
与预算预留。重建已提交事件不得重复增加逻辑请求、缓存命中、收费或状态变化。
不能从顶层重新审计再把额外请求声称为与不中断运行完全一致。

网络结果不确定：
- 已发送但未收到可确认结果的请求，标记 uncertain；
- 保留已占用请求配额与相关预留，不自动重发；
- 不能宣称精确控制外部服务最终账单；
- 该提取返回 UNKNOWN，继续或停止按协议执行；
- 不得把失败当成功，也不能静默跳过该场景以美化平均分。

恢复前核对：
语义配置、协议、数据/证据哈希、规则/提示词/模式版本。
语义变化必须创建新运行，不能复用旧日志充当相同实验。
输出中注明 completed / budget_exhausted / failed / not_run 等状态。

==================================================
14. 查询与指标：同时衡量正确、可用与成本
==================================================

修复结束后先冻结状态与哈希，再评价。
所有方法使用同一个只读 QueryReader：
- 查询指定 logical_id/claim_key、owner/scope、有效时间；
- 返回当前 ACTIVE 合法版本，或者 ABSTAIN；
- 不在查询时额外读原文、重算或修复；
- 不把隔离节点悄悄重新放入回答；
- 主实验使用精确结构化答案，展示自然语言只是模板渲染。

主要指标：
1. overall_accuracy = 正确回答数 / 全部问题数；ABSTAIN 计未正确。
2. coverage = 有明确答案数 / 全部问题数。
3. selective_accuracy = 正确回答数 / 有明确答案数；分母 0 时 NA。
4. stale_error_reuse：
   在初始值错误且更正后应改变的非根查询目标上，最终仍输出旧错误值的比例。
   分母固定为这类查询总数，不能只用“成功恢复的案例”做分母。
   ABSTAIN 不算回流，但会损失 coverage/overall_accuracy。
   直接根问题的正确率单列，避免已知根更正掩盖下游残留。
5. benign_unavailability：
   初始可用且更正后其旧值仍正确的逻辑记忆中，最终没有任何正确 ACTIVE
   当前版本的比例；同值正确后继视为保留。
   这个集合包含依赖图后代中仍然正确的结论，不能只按“非后代”定义。
6. residual_wrong_active：
   设 W0 为修复前值与更正后 gold 不一致的逻辑节点集，Wf 为修复后仍有
   错误 ACTIVE 当前值的节点集，N 为原始逻辑节点数。
   global_wrong_active = |Wf|/N；original_error_residual = |Wf∩W0|/|W0|。
   新引入错误单列 |Wf-W0|，不要用 |Wf|/|W0| 混淆残留和新错。
   分母为 0 时 NA，并单列非根结果。
7. 正确恢复数量、UNKNOWN 原因、修复/隔离/恢复数量。
8. 实际核验单位、读取/规则/模型成本、时间。
9. 诊断：补充候选召回、恢复边数量、核验数；
   使用 gold 的诊断只能在最终 evaluator 中计算，不能反馈排序。

非破坏性系统的“物理误删率”可能恒为 0，不能以它替代正确记忆不可用率。
不要把“原错误停止出现”自动写成“已正确回答”。

报告语义：
stale_error_reuse 是“根更正后，下游旧错误被继续复用”；
它不等于“已经修好的节点经过新一轮写入后再次变错”。
要研究后者，需另建后续写入阶段；v0.1 不做。

统计：
- 独立单位为基础场景，而不是单个问题、节点、预算副本或删边副本。
- 方法用相同场景/缺边/预算条件配对比较。
- 先每场景聚合，再跨场景平均，必要时按生成种子分层。
- 配对 cluster bootstrap 重采样基础场景，所有方法/条件使用相同采样索引。
- 给置信区间、样本量和分布明细；smoke 不做显著性结论。
- 不把 3 个种子简单等同只有 3 个场景，也不把一个图的变体当独立图。
- 缺失、失败、未运行必须报告 planned/completed 数量，不能只展示成功子集。

15. 默认配置与运行规模
==================================================

五个主方法均运行；以下“场景数”指每个种子在 test 中的基础场景数。
dev 使用独立实体/场景，smoke 8 个，pilot 每种子 8 个即可。

pilot：
- 3 个生成种子，每种子 24 个 test 场景；

- 缺边率 [0, 0.25, 0.5, 0.75]；

research：

这些是预设规模，不是已测得的速度/费用保证。

full_audit 仅做独立参考，不计入上述五方法矩阵数量。

18. 必须通过的有意义测试
==================================================

至少覆盖：

A. 领域与证据
- 16→8 后 >=12 为 FALSE、>=6 仍 TRUE。
- (A AND B) OR (C AND D) 中缺一个必要支持不能判 TRUE。
- 一条支持路径失效而另一完整路径有效时，保留结论。
- UNKNOWN 不等于 FALSE；AND/OR 短路与类型规则正确。
- 旧 capsule 不能恢复被撤回的旧根事实。
- UPDATE 保留旧时间区间事实；CORRECTION 修正对应区间；不同 scope 不覆盖。
- 循环/非法类型/超界记录明确失败。

B. 信息隔离
- 公共 schema 不含完整 recipe/真值字段。
- evaluation/ 不存在时 repair 仍可完成。
- 只改变 gold/未来问题及其顺序，保持可见输入相同，修复动作不变。
- 未经 READ_CAPSULE 不可取得隐藏父节点与配方。
- 所有恢复边对应一次实际付费读取。
- capsule 缺失返回 UNKNOWN，不从 gold 回填。
- 完整与缺边场景中的 G_obs 确实不同，遮蔽是嵌套的。

C. 方法与状态
- root_only 不会顺便修复下游。
- graph_only 不会偷偷扫描全文补边。
- expanded_fifo 与 tracepatch 使用同一候选构造和核验器。
- 语义相似不能直接判错或硬删除。
- 在证据齐全且预算足够的固定案例中，正确记忆最终保留；
  缺原文或预算不足时允许出现正确记忆不可用，并在指标中产生代价。
- 未付费检验的旧 ACTIVE 输入不能作为有效证书。
- 版本/证书变化使缓存正确失效。
- 同一个事件重复处理不重复写入或扣费。

D. 预算、恢复与运行模式
- 每个原子动作预留后执行，预算永不透支。
- 失败读取、递归子核验、重试有账目。
- 跨方法缓存不能提供免费信息。
- B=0 不能读取任何额外证据。
- 中途终止后离线恢复与完整运行状态/账本一致。
- 默认模式和测试不访问网络，即使环境中存在 API key。
- live uncertain 请求不自动重发。
- replay 核对请求和语义配置，不因运行目录变化误拒绝。

E. 指标
- 手算小记录验证分母与 NA。
- 全隔离导致 coverage 与 overall_accuracy 降低。
- 同值正确后继计入保留，隔离计入不可用。
- 旧错误复用与任意错误答案分开。
- 配对统计使用基础场景与相同重采样索引。
- 报告数字对应原始记录，模型文本被转义。
- freeze 后修改配置/状态会被发现。

不要为低风险排版修改反复增加无意义测试；
优先验证上述会影响结论的行为。
